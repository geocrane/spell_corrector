## Часть 1. Ошибки логики приложения (баги фильтров/защит)

### 🔴 Bug #1. `_suppress_quote_changes` восстанавливает любые удаления, не только кавычки

**Где**: `spell_checker.py:519-521`

```python
elif op == 'delete':
    out.append(original[i1:i2])     # ← откатывает ВСЁ удаление
```

**Сравним** с правильным `_strict_protect_quotes` (562-568):
```python
elif op == 'delete':
    chunk = orig_chars[i1:i2]
    if any(c in _ALL_QUOTES for c in chunk):  # ← проверка на кавычку
        out.extend(chunk)
```

**Эффект**: при `strict_protection=False AND auditor_format=False` (только тогда вызывается non-strict `_suppress_quote_changes`) любая модельная правка типа «удалить лишнее слово» — отменяется.

**Проверка**: 
```
Input: 'На на следующий период.'
Model: 'На следующий период.'         ← правильно
After normalize step 6: 'На на следующий период.'  ← ВЕРНУЛОСЬ удаление!
```

**Фикс**:
```python
elif op == 'delete':
    chunk = original[i1:i2]
    if any(c in _ALL_QUOTES for c in chunk):
        out.append(chunk)
    # иначе — пропускаем удаление (как и в strict_protect_quotes)
```

### 🔴 Bug #2. `_suppress_colon_insertion` стирает сопутствующие правки в replace-блоке

**Где**: `spell_checker.py:428-434`

```python
elif op == 'replace':
    new_chunk = corr_words[j1:j2]
    if any(':' in w for w in new_chunk) and not any(':' in w for w in orig_words[i1:i2]):
        result.extend(orig_words[i1:i2])      # ← откатывает ВЕСЬ блок целиком
    else:
        result.extend(new_chunk)
```

**Эффект**: один присутствующий в новом chunk-е `:` отменяет все остальные изменения в этом куске диффа.

**Проверка**:
```
Input: 'Контракт включает три части предмет, цена, срок.'
Model: 'Контракт включает три части: предмет, цена, срок.'  ← добавил `:`
Final: 'Контракт включает три части предмет, цена, срок.'   ← откат
```

**Фикс**: разделять обработку `:`-символа и обработку остального содержимого. Например, после получения `new_chunk` удалить из него `:` посимвольно, а остальной текст принять. Или работать на уровне символов с фильтром только `:`:

```python
# черновой подход: удалять только символ ':' и соседствующие пробелы,
# не выкидывая весь блок
new_chunk_no_colon = [w.replace(':', '').strip() or None for w in new_chunk]
result.extend([w for w in new_chunk_no_colon if w])
```

### 🟠 Bug #4. `_normalize_corrected` первого шага опирается на одинаковый индекс буквы в orig и result

**Где**: `spell_checker.py:621-624`

```python
oi = next((i for i, c in enumerate(original) if c.isalpha()), -1)
ri = next((i for i, c in enumerate(result) if c.isalpha()), -1)
if (oi >= 0 and ri >= 0 and result[ri].lower() == original[oi].lower()):
    result = result[:ri] + original[oi] + result[ri + 1:]
```

Это **в целом корректно** для случая «оба индекса найдены». **Однако** условие `result[ri].lower() == original[oi].lower()` срабатывает только если буквы фонетически совпадают. Поэтому в кейсе `ивановА.С.не…` → модель отдала `Иванов А.С. не подписал документ.`:
- `oi=0` → `original[0]='и'`
- `ri=0` → `result[0]='И'`
- buf совпадает по lower → `result = 'и' + result[1:]`

Поведение по спецификации правильное (сохранить регистр оригинала), но **семантически вредное**: пользователь явно ошибся, написав «ивановА.С.не» без пробелов; модель восстановила и капитализировала, а нормализация откатила. **Рекомендация**: подавлять смену регистра только если первое слово оригинала длиннее 1 символа и не идёт сразу за разделительным символом без пробела (детект: 2-я буква оригинала — `isalpha=False`).

**Дополнительный риск** (см. `test_normalize_first_letter_BUG_with_leading_space` — PASSED): ведущие пробелы убирает `_sanitize_text` (`.strip()` в конце), поэтому индексы 0/0 не разойдутся. Так что для production-сценария этот риск не активирован — но если когда-нибудь sanitize выключат, баг проявится.

### 🟠 Bug #5. `_strict_protect` восстанавливает удалённые слова даже когда удаление — это удаление дубликата

**Где**: `spell_checker.py:362-363`

```python
elif op == 'delete':
    result.extend(orig_words[i1:i2])   # ← откат удалений
```

**Эффект**: при `strict_protection=True` (рекомендуемая конфигурация) модель никогда не сможет удалить ничего лишнего: ни дубликат «по по», ни «нет нет», ни лишний дефис «— —».

**Фикс-предложение**: при `delete` проверять, является ли удалённое слово дубликатом соседнего слова в оригинале:
```python
elif op == 'delete':
    chunk = orig_words[i1:i2]
    # Допускаем удаление, если каждое удалённое слово == предыдущему по тексту
    # (т.е. это дубликат)
    is_duplicate = all(
        i1+k > 0 and chunk[k].lower() == orig_words[i1+k-1].lower()
        for k in range(len(chunk))
    )
    if is_duplicate:
        pass   # принимаем удаление
    else:
        result.extend(chunk)
```

Это узкий безопасный путь — разрешать модели исправлять только то, что **точно** дубликат соседнего токена.

### 🟠 Bug #6. `_protect_tokens` не защищает токены с дефисом, латиницей или umlaut

**Где**: `_is_protected_token` (`spell_checker.py:238-260`)

```python
stripped = token.strip('.,;:!?…—–-()[]{}"\'"«»')
if len(stripped) >= 2 and stripped.isupper() and stripped.isalpha():
    return True
```

`isalpha()` для `'Шольц-Müller'` → False (есть `-`). `isupper()` для смешанного регистра — False. Не защищается, и модель меняет `Müller → Muller`.

**Фикс-предложение**: расширить определение защищённого токена:
1. Любой токен, содержащий **не-кириллические Unicode-буквы** (`'A' <= ch <= 'Z' | u00C0..u024F | …`), длиной ≥ 3, считать защищённым.
2. Токен, содержащий хотя бы одну заглавную **и** хотя бы один дефис, считать защищённым (имя собственное).

```python
import unicodedata
def _is_protected_token(token):
    # ... существующие проверки
    if any(unicodedata.category(c).startswith('L') and not ('А' <= c.lower() <= 'я' or c in 'ёЁ') for c in token):
        # есть НЕ-кириллическая буква — иностранное слово
        return True
    if '-' in token and any(c.isupper() for c in token):
        return True
    return False
```

### 🔴 Model #1. `₽` ломается на BPE-токенизаторе → выход «$$», «$^^», «$<...>»

**Примеры из model_raw** (защищается `_protect_tokens`, но видно, что модель НЕ может ничего полезного сказать о тексте с `₽`):

```
'Доход 1 млн ₽.'         → model: 'Доход 1 млн $<...>'
```

1. Перед `checker.check()` заменить `₽` на placeholder, например `RURUB` (3-словная заглавная аббревиатура — модель её и так не тронет; bonus — `_is_protected_token` уже её защитит).

```python
_RUB_PLACEHOLDER = "ZZRUBZZ"
def check(self, text):
    text2 = text.replace('₽', _RUB_PLACEHOLDER)
    ...
    result = ...
    return result.replace(_RUB_PLACEHOLDER, '₽')
```

### 🔴 Model #2. `№N` → `3N` (числовая галлюцинация)

```
'См. Приложение №5 к договору.'  → model: 'См. Приложение 35 к договору.'
'Приложением №4 к договору…'     → model: 'Приложением 34 к договору…'
'В приложении № 3 указаны…'      → model: 'В приложении 3.3 указаны…'
```

Та же причина — BPE-токенизатор не имеет хорошего токена для `№`. Pattern: префикс `3` (видимо, это какая-то BPE-цепочка).

`_protect_tokens` восстанавливает `№N`. **Но** в auditor-формате должно быть `Приложение 5` (без №). Получается, что финал-замена `auditor`-формата НЕ срабатывает, потому что `_protect_tokens` вернул `№5` (с №), и regex `Приложение №\s*` находит правильно. Так что итог почти всегда правильный. Один проблемный кейс:

```
'К приложениях №2 нет замечаний.' → model: 'К приложениям 32 нет замечаний.'
```

Здесь модель попыталась исправить грамматику («приложениях» → «приложениям»), но **`_protect_tokens` посчитал `№2/32` защищённым** и восстановил `№2` → правка грамматики потеряна.

**Рекомендация**: `_protect_tokens` должен сохранять **только токен с цифрой как часть значения**, а не «весь токен включая предлог/окончание». Сейчас выравнивание по `.split()` слишком грубо. Возможный подход: разбивать не по `.split()`, а по слова+пунктуация (`re.findall(r'\S+|\s+')`), и аппроксимировать только цифровые префиксы/суффиксы.

### 🟠 Model #3. Семантические галлюцинации

Реальные галлюцинации модели на простых текстах:

| Input | Model output | Должно быть |
|---|---|---|
| `Превед, как дила?` | Перевед, как дела? | Привет, как дела? |
| `Скуратор прислал зомечяние.` | Скуратор прислал замечание. | Куратор прислал замечание. |
| `Бугалтер закроет переод в пятницу.` | Бугалтер закроет период в пятницу. | Бухгалтер закроет период в пятницу. |
| `Пожалусто, проверти запоси в журнале.` | Пожалуйста, проверьте запости в журнале. | Пожалуйста, проверьте записи в журнале. |
| `Поясните метод деректного перехода…` | …метод директного перехода… | …метод прямого перехода… |
| `Контрагент Шольц-Müller GmbH в реестре.` | …Шольц-Muller… | …Шольц-Müller… (umlaut потерян) |

**Причина**: дистиллированная модель `sage-fredt5-distilled-95m` имеет ограниченное покрытие — некоторые опечатки она не «видит» (не исправляет), некоторые — гадает (галлюцинирует). Это базовое ограничение модели; решение — дообучить адаптер на корпусе бухгалтерских/аудиторских ошибок (`adapters/` сейчас пуст).

### 🟠 Model #5. Не удаляет дубликаты слов

```
'Это это очень важный пункт.'             → unchanged
'Сторона по по договору обязана.'         → unchanged
'Сумма сумма штрафа составляет.'          → unchanged
'В договоре нет нет особых условий.'      → unchanged
'По по итогам проверки замечаний нет.'    → unchanged
```

(Удаляет в 2/10 кейсах: `На на` и `— —`.) Это типичное слепое пятно дистилляций seq2seq — модель копирует input как есть.

**Рекомендация**: добавить **детерминистическую пост-обработку дубликатов** независимо от модели. Это безопасный фикс (не зависит от качества модели).

```python
# В worker() после _normalize_corrected:
corrected = re.sub(
    r'\b(\w+)(\s+\1)+\b',
    r'\1',
    corrected, flags=re.IGNORECASE
)
```

Но **внимание**: «нет нет», «по по» — это разные классы (служебные слова с допустимыми повторами в речи), их надо удалять только если соседние словарные формы совпадают полностью (для финансовых документов — почти всегда).

## Часть 5. Рекомендации по улучшению

### A. Изменения в `spell_checker.py`

1. **Заменить `₽` на placeholder перед моделью** (Model #1) — простейший импакт-фикс.
2. **Поправить `_suppress_quote_changes` ветку `delete`** (Bug #1) — копия из `_strict_protect_quotes`.
3. **Разрешить удаление дубликатов слов** в `_strict_protect` (Bug #5) или добавить отдельный финальный regex `r'\b(\w+)(\s+\1)+\b'` после нормализации (Model #5).
4. **Не выкидывать весь replace-блок** в `_suppress_colon_insertion` (Bug #2) — удалять только `:`.
5. **Расширить `_is_protected_token`** для иностранных имён и дефисных составных (Bug #6).
6. **Переписать `_apply_only_comma_changes`** так, чтобы оно умело принимать вставки запятых (Bug #3).

### B. Изменения в `core/sentence_split.py`

7. **Учитывать закрывающие кавычки** в `_SENT_END_RE` (Bug #7).
8. **Расширить ABBREV_PATTERN** — добавить `См`, `Рис`, `Ср` (двухбуквенные с заглавной), хотя в тестах кейс прошёл — оставить как есть до фактического фейла.

### C. Изменения в архитектуре

9. **Дообучить адаптер** (`adapters/lora_adapter_v2.1` в config указан, но не существует). Без него модель работает с базовыми весами — это значит, что весь user-config `default_adapter` фикция. **Это самостоятельный вопрос**: либо удалить из конфига, либо положить адаптер.
10. **Защита содержимого кавычек** (Model #6) — извлекать `"…"`/`«…»` как замороженные блоки и подставлять обратно.

### D. Регрессия

- Файлы `tests/test_split.py`, `tests/test_normalize.py` — быстрая регрессия (≤ 1 сек, без модели).
- Файл `tests/test_pipeline.py` — медленная регрессия с моделью (≈ 30 сек).
- Скрипт `tests/report_runner.py` — диагностический прогон с генерацией читаемого отчёта.

Регрессионные тесты вернут текущие PASS-проценты в будущем (сейчас baseline = 149/180 = 82.8 %).

- **Тесты Excel-провайдера** — `split_into_sentences` покрыт, но не сама замена в ячейке.
- **Параллелизм** (cancel_event, generation counter) — не тестировался; тест был бы flaky.
- **Загрузка PEFT-адаптера** — папка `adapters/` пуста, тестирование невозможно.
